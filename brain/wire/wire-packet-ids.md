# Packet ids and the version

Packet ids are per state and per direction, and they change between game versions. Every bot generates them from the vanilla server's own reports and never types them by hand.

## Key files
- clojurecraft `resources/clojurecraft/packets.edn`: `{state {:c2s {name id} :s2c {name id}}}`, generated by `bb datagen` from vanilla 26.1.2 `--reports`.
- clojurecraft `resources/clojurecraft/version.edn`: id `26.1.2`, Java 25, protocol 775, world version 4790.
- typecraft `src/lib/typecraft/protocol/build-protocol.ts`: ids from `packets-raw.json` (the same `--reports`), field layouts from bytecode extraction.

## How it works
- The target is **Minecraft 26.1.2, protocol 775**. All three bots pin it.
- Names are Mojang's (`level-chunk-with-light`, `container-click`, `use-item-on`); clojurecraft keys packets by those names and looks ids up in the table, both ways (`ids`, `names`).
- Play, client to server, starts `accept-teleportation 0, attack 1, ...`; the server-to-client play table has over 130 entries plus four `debug/*` ids.

## Gotchas
- `attack` is play c2s id 1 in 775: a dedicated packet, not `interact` ([[wire-actions]]).
- A version bump is a datagen run plus a re-read of every hand-written field layout; the ids alone are not enough.
