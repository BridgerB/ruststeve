# LOOP.md — the combined race → diagnose → fix → gym cycle to the Nether

Persistent state + procedure for a self-driving loop. The model forgets between firings; this file doesn't. Read it top-to-bottom each iteration, do the work, then **update the "Fixes log" and "Current status" sections** before ending.

## Goal & success criterion

A raw `rust-race-*` bot, starting from nothing, reliably reaches **`the_nether`** — the full overworld→nether chain (wood → tools → iron → smelt → buckets → water → flint&steel → obsidian portal cast → walk through). Reliability and generality over speed.

**DONE when:** a chained `race.sh` run logs `entered the nether` / `RACE GOAL REACHED` for a raw bot, and the `to_nether` gym capstone (`pass = dimension == minecraft:the_nether`) sits at a high pass-rate across random terrain.

## THE LOOP — one cycle, three phases

Old approach ran three separate loops (a gym loop, a race loop, ad-hoc debug fixes). This unifies them into **one cadence** that repeats until the goal is met. Each turn of the cron does one full cycle:

1. **RACE (observe, ~2h).** A `race.sh` bot runs continuously on the current binary; race.sh's own relaunch loop keeps it alive (deaths auto-resume from server inventory via `keep_inventory` + the harness's no-clear reconnect). We do NOT babysit it minute-to-minute — we let it run to see how far the *current* code actually gets on real terrain over a long window.

2. **DIAGNOSE (get the current state + the top blocker).** At the end of the window, snapshot how far the furthest bot got and *why it stalled*: read `race-0.log` (furthest `N/19` step, deaths + their coords, the repeated failure line), `data/gym.db`, and — for interaction failures — a **packet sniff** capture. The output of this phase is ONE named blocker with a reproducible condition (a step, a position, a kit, a symptom).

3. **FIX + VALIDATE (debug the blocker, then harden in the gym).**
   - **Reproduce in isolation** at the blocker's exact conditions using ruststeve's gym / `STEVE_TEST` mode — the equivalent of "spawn into that spot with those conditions": teleport a bot to the failing `x,y,z`, grant the failing kit, run just that step, with `SNIFF` + the relevant `*_DEBUG` flags on. Watch it fail the same way.
   - **Diagnose from the evidence** (packets, debug logs, world state), make **one targeted code fix**, `cargo build --release`.
   - **Harden in the gym (~1h):** run gym trials on the affected step across *random terrain* (the blockers are terrain-dependent — a clean-arena test lies). If the fix holds, pass-rate climbs; if a new hurdle appears, fold that lesson back into the code too.
   - **Relaunch a fresh race** on the improved binary. The next cycle observes whether the wall moved.

The invariant: **every cycle the code is strictly better than the last** — we never end a cycle without either a committed-in-spirit fix or a validated "this step is now green." Log each cycle's blocker + fix in the Fixes log so we never re-fix.

## Tools for the DIAGNOSE + FIX phases

- **Packet sniffer** (`src/sniff.rs`, `SNIFF` env): captures every protocol packet BOTH directions to `data/sniff-<user>.db` with millisecond timestamps, hooked at `Client::write`/`next_packet`. `SNIFF=1` = all; `SNIFF=container,carried,click,use_item,block` = just the craft/scoop interaction surface (stays fast). This is how the two *interaction-reliability* walls get diagnosed — you can see the exact server reply after a click/scoop and how late it was:
  `sqlite3 data/sniff-<user>.db "SELECT ts_ms,dir,name,size,summary FROM packets WHERE ts_ms BETWEEN <t0> AND <t1> ORDER BY ts_ms"`.
- **Gym isolation** (`GYM=<slug>` / `STEVE_TEST=<step_id>`): reproduce one step at a chosen spot+kit; the "spawn into the failure" mechanism. See "The gym" below.
- **Debug flags:** `CRAFT_DEBUG`, `MINE_DEBUG`, `CAST` (via CRAFT_DEBUG), `PKT_DEBUG`, `GOTO_DEBUG`, `DIG_DEBUG`, `CHUNK_DEBUG`.

## The two remaining reliability walls (both server-lag interaction issues)

1. **craft / `click_window`** — under load the container resync is racy; a craft fails `crafting table would not open` / `missing ingredient`. Do **NOT** rewrite the click_window force-resync (load-bearing). Diagnose with `SNIFF=container,carried,click` to see whether the `container_set_content` reply is late/absent, and handle at the retry layer (`craft_item`).
2. **water / lava bucket scoop** — the `use_item` pour/scoop is a POV raycast whose result echo lags; a scoop reports empty though the source was there. The **source-water fix** (scoop only from a real `level=0` source, drop feet to source+1, predict the result when the echo is missing) targets this directly. Diagnose with `SNIFF=use_item,block,carried`.

The blocker was never a single bug — it was a stack, each hiding the next. Fixes, in the order they were peeled back:

1. **Frame anchored INTO the lava** (`bx=px+1` east) → forced a cobble platform over the pool → the bot took lava damage laying it, "retreated up", and the re-captured anchor jumped ~5 blocks high with the pool out of re-scoop reach. → Anchor on the bot's **solid side away from the lava** (`bx = lava.0>px ? px-4 : px+1`; `fill_bucket` walks ≤24 blocks to the source so re-scoops still work) + **lock the anchor height** to the scoop level (`by = stand.1`).
2. **Both fluid pours were free-aim raycasts** that missed ~half the time → stray lava pooled around the frame and the bot fell in and **died**. → **Deterministic `place_block` on a face**: lava on the cup floor's top, water on the bowl's -Z wall — lands exactly in the target cell.
3. **Top-row-first** put lava cups up high → the bot couldn't descend past its own cup lava (`DESC LAVA-STOP` spin). → Cast **bottom-up**.
4. **Portal wouldn't light**: the 2×3 interior wasn't pure air (`build_inner_fill` scaffold + water from the bottom-row cup bowls, which land IN the interior; `dig_at` removes solids but not water). → **Robust interior clear**: scoop water + dig scaffold, reposition per cell, retry until all air.
5. **Re-scoop over a depleted lake rim** stood the bot on lava (20→0 hp faster than the per-round guard). → **Early bail** the instant health drops in the scoop loop + **wider gym lake**.
6. **Entering the Nether crashed the bot**: the respawn packet updated `game.dimension` but not `min_y`/`height`, so the chunk parser kept the overworld's 24-section count and overran the shorter nether chunk buffer (`chunk_section.rs:101`, index==len). → Set height per dimension on respawn: **nether/end → (0, 256)**, else (-64, 384).
7. Plus: **fail-fast on death** (don't spin the budget in dead-limbo), and **respawn→arena re-tp** in the gym (a mid-build death otherwise stranded the bot at world spawn).

**Known caveat / next focus:** the frame build is not yet 100% reliable — it still takes an occasional lava death mid-build (roughly half of runs), and the top-row cast is slow (~15 min). The respawn re-tp lets a death retry, but reliability + speed of the cast are the remaining work before this is race-ready.
