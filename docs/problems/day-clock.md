# Issue 16: the day clock (the bot did not know the time of day)

## Needs
The overworld leg's bots spend 10,000 to 13,000 ticks on the surface hunting and cooking, about half a Minecraft day, and die to night mobs after it (a creeper killed one at tick 15,780, after dark). A player plans around dusk. The bot could not: `S2c::SetTime` was a unit variant, decoded fieldless, and the bot counted the packet (20 server ticks each) without reading the time.

## Done (world terms)
The world holds the time of day from the server's own `set_time`, a pure query answers "is it night" and "how long to dusk / dawn" with the game's own numbers, the ledger says when night falls and day breaks, the senses rows show the time, and the server model sends the time as a real server does. Proven on real bytes cut from a recording, in closed loop on the model, and by re-reading a recording with `replay ledger`.

## Risks
- `S2c::SetTime` became a struct variant (`SetTime { game_time, clocks }`): every `S2c::SetTime` pattern in another branch must become `S2c::SetTime { .. }`, and every literal `S2c::SetTime` must name its fields (`game_time: 0, clocks: Vec::new()`). On this branch that was protocol's session and state, world, sim and three tests. Recordings are unaffected: they hold each packet's bytes and replay decodes them again (`crates/record/src/lib.rs`).
- `World` gained `game_time` and `day_clock` with `#[serde(default)]`: an old checkpoint reads, with no clock. A recording made before this commit and verified with `--force` differs at its checkpoints by these two fields, as any fold with newer code does.
- The `world_clock` registry ids are not read from the wire (the bot reads no registry): id 0 is taken to be `minecraft:overworld` because synced registries go out sorted by name (the dimension types are: 3 is the Nether) and the jar's `data/minecraft/world_clock/` holds `overworld.json` and `the_end.json`. In the real bytes both clocks carry the same ticks, so a wrong id would not show today.

## Wall 1: the time was on the wire and thrown away
- **The read.** The 26.1.2 server jar (`META-INF/versions/26.1.2/server-26.1.2.jar`), read with `strings` on the classes. `net/minecraft/network/protocol/game/ClientboundSetTimePacket` is a record `(long gameTime, Map<Holder<WorldClock>, ClockNetworkState> clockUpdates)` whose codec is `StreamCodec.composite(ByteBufCodecs.LONG, ..., ByteBufCodecs.map(HashMap::new, WorldClock.STREAM_CODEC, ClockNetworkState.STREAM_CODEC), ...)`. `WorldClock.STREAM_CODEC` is `ByteBufCodecs.holderRegistry(Registries.WORLD_CLOCK)` (a varint registry id). `ClockNetworkState` is `(long totalTicks, float partialTick, float rate)` with `VAR_LONG, FLOAT, FLOAT`. So: an i64 game time, a varint count, then per clock a varint id, a var-long, two floats. This is no longer the 1.21 layout (two longs and a flag) the old encoder wrote.
- **Real bytes.** Probe 45359992340 (`replay export`, every packet id 113) on race 45355573039 lane 0 (commit be2197a) and race 45350933958 lane 1 (commit a267f6d), both bots in the Nether. The join's `set_time` is 33 bytes: `0000000000013447 02 00 c7e804 00000000 3f800000 01 c7e804 00000000 3f800000`: game time 78,919; clock 0 and clock 1 both at 78,919 ticks, partial 0, rate 1. Every later one is 9 bytes, the game time and a count of 0 (599 in the first run, 485 in the second; none with clocks). The server sends the clocks once and the client runs them on.
- **The day's numbers.** The jar's `data/minecraft/timeline/day.json`, the overworld clock's timeline: `period_ticks` 24000; `gameplay/monsters_burn` false at 12542 and true at 23460; `gameplay/sky_light_level` 1.0 to 11867 and 0.27 from 13670 to 22330; markers `day` 1000, `noon` 6000, `night` 13000, `midnight` 18000. The dimension types name the clock: overworld `default_clock: minecraft:overworld`, the End `minecraft:the_end`, the Nether none.
- **The fix.**
  - `protocol`: `S2c::SetTime { game_time: i64, clocks: Vec<ClockUpdate> }`, `ClockUpdate { clock, total_ticks, partial_tick, rate }` in wire order, `OVERWORLD_CLOCK` = 0; the encoder writes the same layout. Tested on the real bytes (`crates/world/tests/day_clock.rs`: decode, and encode back to the same 33 bytes) and by the encode round-trip property.
  - `world`: `World::game_time`, `World::day_clock` (the overworld clock as last told: its ticks, the game time it came with, its rate). `World::day_time() -> Option<i64>`, 0 to 23,999: the clock run on by the game ticks since at its rate, so the 9-byte packets move it. `World::is_night() -> Option<bool>`.
  - `world::time` (pure): `DAY_TICKS` 24000, `DUSK` 12542, `DAWN` 23460, `of_day`, `is_night(day_time)` (`DUSK..DAWN`: undead do not burn and surface monsters spawn), `ticks_to_dusk(day_time)` (0 at night), `ticks_to_dawn(day_time)` (0 by day). Unit-tested.
  - `sim`: `Sim::day_time` (0 at a new world, one a tick; a test sets it), sent as a real server does: both clocks in the first `set_time`, then the game time alone.
  - `observe`: `Fact::Night { day_time }` when night falls or the bot joins at night, `Fact::Day { day_time }` when day breaks (`night fell (day time 12550)`, `day broke (day time 23460)`); `Senses::day_time`, printed `day 18887 night` in the senses text.
- **Proof.** `crates/world/tests/day_clock.rs` (real bytes: the join at 6919, the run's end at 18,887, night, 4,573 ticks to dawn); `crates/bot/tests/day_clock.rs` (closed loop on the model: one nightfall within one sync of `DUSK`, one daybreak within one sync of `DAWN`, rows carry the time). Probe 45360831592 re-read race 45355573039 lane 0's recording with this build (`replay ledger <rsr> --force --senses 60`): the ledger now says `5660 night fell (day time 12547)` (within one 20-tick sync of `DUSK`), and the senses rows run `day 6927` at server tick 40, `day 11727` at 4840, `day 12927 night` at 6040, `day 17727 night` at 10840: one day tick a server tick, in the Nether too.

## For the planner (agent O)
`world.day_time()` (the time of day, `None` before the first `set_time`), `world.is_night()`, and `world::time::{is_night, ticks_to_dusk, ticks_to_dawn, DUSK, DAWN, DAY_TICKS}`. In the Nether and the End the overworld clock still runs (the join sends it; it is the overworld's time, not the dimension's sky).
