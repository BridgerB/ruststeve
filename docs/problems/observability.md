# Issue 16e: full observability (the one major change)

## Needs
Any failure of any remaining stage (issues 16 to 20) is explained from one race's files in minutes, without a probe; and the bot can sense what those stages need (tool wear, sounds, gaze, fuse, the dragon's phases). `brain/ruststeve/design/observability.md` has promised this since issue 07; on 2026-11-21 most of it did not exist.

## Done (world terms)
A real race's summary prints a coverage row with no `!!`: every run has its case, recording, ledger, senses, moments and server truth; every task the planner started has a reason and an end; no ledger event dropped; no item slot or entity data cut short; no wanted packet thrown away. Three case files opened at random each answer, in ten seconds, how the run ended, what the bot was doing then and why, and its tool and item story. Walls 5, 6 and 7 of `blaze.md` can be rewritten from the new tools alone.

## Risks
Planner code churn (about 90 note sites become typed events); recording and case formats must grow by accretion only; the core must stay pure (the ledger and senses are pure functions, only the bot writes files); server truth must never reach the planner (no X-ray); lanes must not slow under the extra writing (the ledger has its own thread and counts drops instead of blocking).

## The last recorded failure (why this is first)
Issue 16 stopped on 2026-11-21 under the loop's 12-hour rule after three walls in a row, each found only after a 3-to-4-hour race and probes:
- Race 44947909226 printed "unknown packets 2,531,033" (about 211,000 a run, unread). About 37 of 141 play packet kinds were decoded; sounds, level events (a blaze's shot is 1018), equipment, gaze, fuse, chat, effects and boss bars were thrown away.
- Tool durability was parsed and discarded (`protocol/src/slot.rs`), so a broken stone pickaxe was only "items lost: stone_pickaxe 1" at the end, and the planner could not see wear: `goals.toml` declares a spare pickaxe, but a nearly broken one counted. That is wall 7's direct cause.
- The planner kept 64 string notes; the case file kept 240 and printed "notes left out: 4417". Every case's signature was the same ("aim race / the planner (issue 09)").
- No health or food over time, no item ledger, no senses, no moments, no truth; races ran four hours with no look inside, so a forgotten `-f minutes=240` cost a race (44942537213) and 11 of 12 bots sat stuck for 2.5 hours in race 44947909226.

## Phases (one PR each unless noted, into `main` from `issue-16e-observability`)
- **A. A coverage row that cannot lie.** Every clientbound packet classified as decoded, wanted or skipped (`config/observe.toml`, tested); unknown packets counted by name; every output a run should leave has a column, and a column not measured prints `not measured !!`; the case signature names what the planner did at the end. *Built: this PR.*
- **B. Hear and see what the server sends** (four PRs): item components kept (durability: `uses_left`), every entity-data serializer read and named per entity from the jar; sounds, level events (named), stop sounds; equipment, head rotation, projectile power, hurt and swing animations, passengers, explosions, block-entity data (the blaze spawner), block cracking; effects, attributes, combat enter/end, experience, cooldowns, game events, time, chat and titles, boss bars, biomes, view and simulation distance.
- **C. The ledger, senses and moments** (three PRs): a typed `BrainEvent` (task started and ended with a closed `Reason` branch, goal and the needs planner's trail; child steps; choices; refusals; the failure enums unchanged inside `Outcome`; fight and cast accounts; resources per unit of progress), in a new pure `observe` crate, one clock (server ticks); `observe::diff` for world facts (health, food, hits with amounts, what set the bot alight, item changes, tool worn and broken, sounds, mobs appearing, facing, angry, fusing, charging); a senses row every second; classes (freeze, idle, swarm, burning, watched, starving, toolless, deep); a moment ring; the case rebuilt from the ledger, never cut.
- **D. Truth and blind spots**: RCON `data get entity` around the bot at the end and each minute of the last five (real), the model's view (sim), the server log's lines; `blind:` lines where belief and truth differ. Truth lives only in the shell.
- **E. See a race while it runs**: `Ending::NoProgress` after 20 minutes with no progress (counted, with its case); a progress table uploaded to the release every 10 minutes; a pre-flight that refuses a cap that does not fit the job's minutes.
- **F. Tools that answer without a probe**: `why --ledger`, `replay timeline`, `replay ledger` (rebuilds a ledger from an old recording: every packet's bytes are in it), `results cases`, the same on the MCP server, ledger and senses tables in the insight store.
- **G. Per-stage senses for issues 16 to 20**: the blaze volley line and fire causes (16); ticking against frozen endermen, biome, distance per dig and per pickaxe, choice flips (17); each enderman's story and the look-away event (18); each eye throw and the triangulation against truth (19); the dragon's phase, boss health, crystals and breath (20).
- **H. Prove it on races already run**: walls 5 to 7 re-read from races 44919152494, 44947909226 and 44970722653 with the new tools, without a probe.
- **I. The gate, then back to the bot**: AGENTS.md section 4 and `decisions/observe-first.md` (no behaviour PR while the coverage row shows `!!`; every wall cites ledger lines; every fix counts its new path's firings); then wall 7 (worn tools are not spares, keep the table, a wood reserve, back away from a fusing creeper) from a fresh surface `gear` snapshot.
